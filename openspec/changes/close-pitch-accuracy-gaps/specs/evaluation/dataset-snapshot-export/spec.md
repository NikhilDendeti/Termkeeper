## Purpose

Turns the synthetic dataset from "regenerable on demand" into an actual committed artifact, so the buildathon's preference for batch-level, non-cherry-picked evidence is backed by a real file in the repo, not just a promise that the generator works.

## ADDED Requirements

### Requirement: Dataset export is portable and complete
The system SHALL be able to export a generated dataset version to a single JSON file containing every contract's raw text, engagement id, generation parameters, and every associated EvalLabel — enough to reconstruct what was generated and labeled without re-running the generator.

#### Scenario: Export contains every generated contract
- **WHEN** a dataset version with N contracts is exported
- **THEN** the export file contains exactly N contract entries, each with its raw_text and every EvalLabel generated for it

### Requirement: A committed snapshot exists for the default dataset version
The repository SHALL contain a committed export file for dataset_version "v1", generated by the same exporter this change adds, not hand-authored.

#### Scenario: Committed snapshot is internally consistent
- **WHEN** the committed v1 snapshot file is inspected
- **THEN** its contract count is within the project's stated 30-50 range and every engagement_id in it matches the naming convention `synthetic-v1-<n>` already used by the dataset generator
